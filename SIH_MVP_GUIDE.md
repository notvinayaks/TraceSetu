## The USP

**“Find the first evidenced receiving VASP, explain why it is the nearest supported answer, and show exactly what evidence could change that answer.”**

The distinguishing demonstration combines four working capabilities:

1. **A bounded custody frontier:** each branch stops at its first supported custodian. Missing shallow paths, ambiguous order and conflicting labels remain visible. An exchange withdrawal is not treated as a continuation through the exchange's private customer ledger.
2. **An inspectable nearestness certificate:** the answer binds to its snapshot, time window, asset and traversal limits. It distinguishes the nearest known target in that snapshot from the unknown nearest VASP in the real world.
3. **A source challenge:** remove an assertion's provenance family and recompute the answer. Investigators can see whether one weak source is carrying an attribution.
4. **Budgeted next-evidence execution:** select a request budget, inspect the proposed frontier queries and execute them into a new result. The request cap survives worker recovery, parent evidence is preserved, and contradictory event observations remain withheld.

Together these make uncertainty actionable and the evidence reproducible. They are an implemented product proposition, not a claim of world-first invention or measured superiority over commercial services. Investigation-time reduction and cost savings require a comparative user/data evaluation.

## Every problem-statement requirement, mapped honestly

| Requirement | Working MVP behavior | Boundary / remaining dependency |
|---|---|---|
| Analyse reported suspect wallets through APIs | Authenticated case and analysis APIs, input validation, durable jobs, imports and provider mode | Receiving an actual SAHYOG report requires its official contract and credentials. |
| Nearest exchange/custodial service/direct-deposit receiver | Chronological first-custody traversal, deposit-role assertions, direct and multi-hop candidates, conflict/unknown states | A deposit role requires sourced evidence. Missing identity labels cannot be inferred from transactions alone. |
| Bitcoin, Ethereum, Tron, BNB Chain, Solana, Polygon | Six bounded read-only chain adapters with exact amount normalization and raw-response preservation | Parsers are tested with explicit synthetic inputs. Real endpoints/entitlements and independent per-chain examples still require validation. Other chains are future adapters. |
| Exchange clusters, hot wallets and deposit wallets | Source assertions carry cluster/hot/deposit/unknown roles; reviewers control their promotion | Automated ownership clustering is not implemented. A cluster assertion is not beneficial-owner identification. |
| Mixers/tumblers | Source-labelled mixer boundary stops deterministic traversal | No guessed mapping from mixer deposits to withdrawals. |
| DeFi bridges and cross-chain mapping | CCTP V2 native-USDC Ethereum/Polygon proof correlation, review, graph and report inspection | Other bridges require separate verified decoders and trust analysis. |
| Cross-chain swaps / DeFi | Unsupported asset/protocol transitions are exposed as unresolved; service categories can be represented by assertions | General swap/aggregator decoding and opaque off-chain swap correlation are not implemented. |
| Blockchain intelligence and graph analytics | Provider adapter layer, strict assertion/proof contracts, deterministic graph engine and interactive graph | Commercial attribution data needs licensed API access; a transaction-history API is not an ownership database. |
| Automated tagging and confidence scoring | Source-linked service/risk tags, reviewed/provider/hypothesis grades, evidenced/conflicted/hypothesis result states and a nearestness certificate | Grades are categorical confidence evidence. Calibrated percentage scores are deliberately absent until independent labels support them. |
| LEA investigation reports | PDF, JSON, CSV, preserved raw evidence, signed manifest and offline/UI replay | Admissibility and agency report acceptance are institutional decisions; signatures establish integrity. |
| Route lawful disclosure/freezing requests | Candidate-to-recipient matching, expiry checks, two-person review, payload binding and export; signed response review | Official SAHYOG transport and real sending are not connected. A prepared freezing-review request is not an asset freeze. |
| Case dashboard and real-time intelligence | Interactive case workbench, queued/running/completed/partial jobs, current local result updates | Provider latency and incomplete history prevent a universal real-time guarantee. |
| Risk and high-risk wallet alerts | Sourced risk categories, explicit unassessed state, watched-wallet case change alerts | No invented criminal label, numerical risk calibration or external notification service. Dedicated laundering-typology detection is future work. |
| Scale / large transaction volumes | Bounded request/state/hop limits, durable local worker and configurable database connection; architecture documented | Current validation is single-node/local. No large-volume performance or production PostgreSQL claim. |
| Reduce time, improve freezing efficiency and cross-border investigations | Query prioritisation, reproducible evidence and reviewed recipient/request workflow support these aims | Benefits are hypotheses until measured. Real freezing and cross-border action require legal authority and VASP cooperation. |

## Demonstrable acceptance and practical cost-saving choices

The complete local backend regression passed **107 tests**, including 18 execution tests. The frontend compiles and builds. All four browser workflows passed against the final build: investigator, independent reviewer, protocol-proof review and selected query execution. They reported zero page errors. The query workflow passed mobile overflow checks, preserved its parent and verified its signed bundle; its two-page PDF was rendered and visually inspected. See `MVP_CHECKLIST.md` for acceptance evidence.

The app can be demonstrated without purchasing an intelligence API: use clearly labelled synthetic scenarios or lawfully acquired evidence imports. Optional permitted public/self-hosted sources and later credentialed providers use the same evidence contracts. Persisted responses are reused after execution recovery, saving duplicate HTTP requests where evidence was already preserved. This does not bypass licensing or establish quantified savings.
